# 数据库查询结果内存边界

交互式查询默认行数来自设置（默认 200 行）。普通执行、批量执行、确认危险 SQL 后执行与事务执行使用同一限行逻辑；仅对 SELECT/WITH 自动追加限行，不修改管理命令及写语句。顶层已有 LIMIT/FETCH/TOP 的查询保留用户 SQL，字符串、注释、子查询内的 LIMIT 不再绕过自动限行。尾部行注释之后追加的限行从新行开始。

MySQL、PostgreSQL、SQLite 通过逐行读取构造结果，避免同时保留完整驱动行列表和完整字符串结果。手动事务走相同读取预算，超限不提交事务，仍由用户提交或回滚。SQL Server 逐项读取结果流，保留首个结果集及 DML 的最终受影响行数。ClickHouse TCP 按块读取并逐行计入预算；HTTP 响应体累计超过 32 MiB 即拒绝继续读取。

单次解码结果预算为 100000 行、32 MiB（字符串 UTF-8 字节与行/单元格结构的逻辑大小）。超限返回中文错误，说明未返回部分结果，并建议缩小查询或流式导出；不会把安全截断当作完整结果。Oracle 移除了旧的静默 50000 行截断，采用相同预算。DuckDB 交互式路径移除了旧的静默 1000 行截断，解码时采用相同预算。结果区关闭会释放单结果、多结果及导出快照引用；运行期间需先停止查询。导出窗口关闭也释放其快照引用。

SQL 草稿在编辑期间完整保留，超过持久化限额不会删除打开标签的草稿。仅持久化快照应用单项 300000 字符、合计 1500000 字符的限制，并优先保留最近编辑的草稿。JSON 编码和浏览器存储写入一起防抖，失焦/编辑器卸载时刷新。

这些限制不等于进程 RSS 上限：

- 多个打开标签、多语句批次可以分别保留结果，没有静默淘汰用户结果的全局缓存。
- 容器容量、分配器、IPC/浏览器字符串、列名、驱动网络帧与单行/单块解码存在额外内存。
- DuckDB 当前使用原生 `duckdb_query`，引擎会先物化完整原生结果，再进行受预算约束的字符串解码；原生物化内存尚不由应用预算限制。
- SQLx、Tiberius、ClickHouse 驱动可能在应用检查之前分配单个巨大行或块；此预算约束累计保留的解码结果，不保证限制驱动内部峰值。
- 未对真实数据库执行验证，也未进行桌面堆快照或 RSS 基准测量。

回归测试涵盖顶层 LIMIT 识别、尾部注释与写语句限行、解码行数/字节预算、SQLite 超限后事务可回滚、空结果列名，以及草稿持久化与完整编辑内容保留。核心命令：`npm test`、`npx tsc --noEmit`、`cargo test commands::query --lib`、`cargo test commands::db_tx --lib`。

## 平台门禁说明（2026-11-15）

`scripts/acceptance/memory-stress.py` 现在只报告临时 SQLite 有界负载的 RSS 测量值，状态为 `MEASURED`，不设置人为通过阈值，也不代表长期运行或完整桌面进程内存已经验收。长期 RSS 仍需在目标桌面环境中持续运行并采集独立进程指标。
