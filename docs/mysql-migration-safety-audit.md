# MySQL 迁移与 DDL 安全审计

验收依据：源端当前 `SHOW CREATE TABLE` 是结构真源。迁移仅允许替换目标表名，不允许自动改列、索引、约束、字符集、排序规则或表选项。不兼容应报错，不得降级后报告成功。

## 已确认的问题

- `mysql_apply_ddl` 删除外键并改写排序规则。
- `CREATE TABLE LIKE` 不复制外键或当前自增计数；无法满足完整结构复制。
- 仅结构迁移进入 `fetch_all`，不必要地读取整表数据。
- 非流式跨连接迁移按列重建，丢失索引、默认值、注释和表选项。
- 部分 replace 分支在数据写入前删除旧表备份，写入失败不能恢复。
- 单表 SQL 导出 DDL 变量恒为空，结构导出漏建表语句。
- ZIP 表 SQL 条目没有 DDL 终止分号，无法连续执行建表与 INSERT。
- 结构化编辑器无法表示函数索引时可能误删唯一索引。

## 实施与验证

- 并行修复迁移保真、DDL 编辑器安全；主任务核对导出和集成。
- 原文替换函数覆盖函数索引、外键、分区、注释、列与表字符集、自增以及异常输入。
- 使用独立本地 MySQL 8.4 临时实例验证源/目标 SHOW CREATE，验证不兼容建表失败时旧表保留。
- 执行前端全量测试、TypeScript 检查、Rust 检查与相关测试。
- 本审计的“源 SQL”指数据库当前返回的定义，数据库不会保存用户最初输入的 SQL 排版或省略写法。

## 安全边界

- MySQL 同家族跨库迁移不允许自动降级排序规则、删外键、按列重建或忽略写入错误。建表后与数据完成后分别比对 SHOW CREATE；仅允许目标表名不同。
- 覆盖旧表先保留备份，失败尝试恢复；恢复或清理失败必须返回具体备份位置。目标有触发器或被外键引用时，拒绝覆盖或清空，避免波及其他表。
- 实际写连接强制开启并验证外键检查，数据迁移要求严格模式、InnoDB 和事务。数据源使用一致性快照，时间会话统一 UTC，保留零值自增 ID。
- 当前跨连接文本传输不支持二进制、BIT、空间、FLOAT/DOUBLE 或生成列数据保真，因此这些字段的数据迁移在修改目标前拒绝；仍允许仅结构迁移。触发器复制和改名自引用外键也拒绝。
- 相同库名及表名的跨连接迁移保守拒绝，避免连接别名指向同一源表。仅数据迁移要求完整结构一致，包括自增计数。
- 结构化编辑器不再通过不完整字段元数据重建已有 MySQL 列，不支持的定义修改需在 SQL 编辑器明确执行原始 DDL；复杂索引不可由摘要误删。
- 导出保留表原始 DDL，补齐语句结束符；SET NAMES 是文件文本解释环境，不等同于数据库默认排序规则。本轮没有自动 ALTER DATABASE，也没有实现完整数据库默认属性备份。

## 验证证据（2026-11-13）

- 前端测试 137 通过，TypeScript 类型检查通过。
- Rust 单元测试 169 通过；另 1 项真实 MySQL 集成测试按默认规则忽略，需要显式指定临时实例端口执行。
- 独立本地 MySQL 8.4.11，源库 utf8mb4 / 目标库 latin1：用户提供完整表定义复制后 SHOW CREATE 一致，没有额外列字符集。
- 实际 open_stream_dst / drive_stream 集成测试通过：函数索引、ON UPDATE、表选项、中文、前导零文本、日期、id=0；不兼容排序规则失败恢复旧表；拒绝 CASCADE 清空且依赖行保留；写连接外键检查开启。
- 真实测试同时发现并修复 MySQL 8.4 的 START TRANSACTION 预处理协议 1295 错误，事务控制改用文本协议。

这些证据针对本轮 MySQL 迁移、复制、DDL 编辑及结构导出修复。并发外部 DDL、其他数据库引擎、完整数据导出类型保真，以及 SSH/SFTP/触摸板/整体内存问题，不由以上测试证明；不作全软件无 bug 或绝对安全承诺。
