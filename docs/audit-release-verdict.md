## 本轮新增：DuckDB 改表批次原子性（2026-11-15）

## 本轮新增：DuckDB 文件导入映射与 skip 行为（2026-11-15）

- 根因：`db_import_csv` 先由 DBterm 解析 JSON/XML/Excel 到已映射行，但 DuckDB 分支随后对 JSON 使用自动推断、对 XML/Excel 仍走 CSV `COPY`；这些路径没有使用解析行和显式 schema/列映射。`skip` 对结构化格式则调用全批原子插入器，首条坏记录会让整批失败，与用户选择的跳过策略不一致。初次原生回归还发现导入 helper 私自打开第二个 DuckDB handle，应用缓存会话无法即时看到其成功写入。
- 修复：JSON/XML/Excel统一使用解析后的记录及目标列顺序，目标引用包含 schema；导入复用应用连接 ID 的缓存 handle，避免同库多个 session 状态不一致。DuckDB stop 模式保持全文件事务。所有格式的 skip 模式按行事务提交合法记录、回滚坏行并填充 `skipped/errors`；开始前校验目标表和列，回滚失败或提交回执未知时中止并提示人工核对，禁止自动重试。CSV/TSV stop 继续保留 DuckDB 原生 COPY 快速路径。
- 原生隔离专项覆盖 schema 限定目标、重排字段/中文换行值、重复键 stop 回滚、skip 保留合法行并准确报告逻辑行号、错误目标预检及同一缓存会话读回写入数据。该测试要求本地校验过哈希的 DuckDB 1.5.3 动态库，默认忽略；未接触业务数据库或凭据。
- 限制：skip 是逐记录提交，后续连接/进程异常可能发生部分成功；前端需要依赖现有的结果核对提示，不具备跨重启幂等性。整个输入文件及解析后的行目前仍全量驻留内存；此修复不解决文件/解压预算、长期RSS、DuckDB COPY 的错误细节回报或所有引擎导入完整性。该专项通过不能代表整体发布验收通过。
